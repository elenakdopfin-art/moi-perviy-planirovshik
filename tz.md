# Техническое задание: веб-планировщик "План на день"

## 1. Назначение продукта

"План на день" — личный веб-планировщик для ежедневного, недельного, месячного и годового планирования. Приложение помогает вести рабочие задачи, детские занятия, домашние и личные дела, задачи по здоровью, а также дни рождения родных и знакомых.

Приложение должно быть простым, уютным, визуально спокойным и удобным для работы на ноутбуке.

## 2. Технические ограничения

Само приложение должно состоять строго из трех файлов:

- `index.html` — структура страницы.
- `style.css` — оформление, сетки, адаптивность.
- `script.js` — логика приложения, работа с датами, задачами, повторениями и `localStorage`.

Запрещено использовать:

- сервер;
- базу данных;
- сборщики;
- внешние библиотеки;
- фреймворки;
- импорт и экспорт файлов;
- авторизацию;
- регистрацию пользователей.

Все данные должны храниться только в браузере через `localStorage`.

Рядом с файлами приложения могут лежать файлы документации проекта (`concept.md`, `tz.md`, `plan.md`) и служебная папка git. Они не считаются частью пользовательского приложения.

## 3. Основной пользователь

В продукте есть один пользователь — владелец личного планировщика.

Пользователь может:

- просматривать календарь в режимах день, неделя, месяц, год;
- создавать задачи;
- редактировать задачи;
- переносить задачи;
- удалять задачи;
- создавать повторяющиеся задачи;
- добавлять дни рождения;
- фильтровать календарь по категориям;
- видеть задачи с временем и без времени;
- видеть приоритеты задач;
- видеть заметки внутри карточек задач, если заметка заполнена;
- видеть тестовые задачи при первом открытии.

Многопользовательского режима быть не должно.

## 4. Язык интерфейса

Весь интерфейс должен быть на русском языке.

Примеры подписей:

- "План на день"
- "Сегодня"
- "День"
- "Неделя"
- "Месяц"
- "Год"
- "Добавить задачу"
- "Редактировать"
- "Перенести"
- "Удалить"
- "Сохранить"
- "Отмена"
- "Категория"
- "Приоритет"
- "Повтор"
- "Без времени"

## 5. Главный экран при открытии

При открытии страницы приложение должно:

- показывать режим "Неделя";
- показывать сегодняшнюю дату;
- загружать задачи из `localStorage`;
- если приложение открывается впервые, добавить тестовые данные;
- если данные уже есть, не перезаписывать их.

Для определения текущей даты использовать дату браузера пользователя.

## 6. Навигация по календарю

В верхней части интерфейса должны быть:

- название приложения;
- текущий отображаемый период;
- кнопка "Сегодня";
- кнопка перехода назад;
- кнопка перехода вперед;
- выбор даты через поле `input type="date"`;
- переключатель режимов: день, неделя, месяц, год.

Логика кнопок назад и вперед:

- в режиме "День" переход назад на 1 день, вперед на 1 день. Например, если открыт среда, назад показывает вторник, вперед показывает четверг;
- в режиме "Неделя" переход назад или вперед на 1 неделю;
- в режиме "Месяц" переход назад или вперед на 1 месяц;
- в режиме "Год" переход назад или вперед на 1 год.

Кнопка "Сегодня" всегда возвращает к сегодняшней дате.

Неделя начинается с понедельника.

## 7. Категории

Категории фиксированные. Пользователь не может создавать, удалять или переименовывать категории.

Список категорий:

- Работа
- Дети
- Дни рождения
- Дом
- Здоровье
- Личное

У каждой категории должен быть фиксированный цвет.

Рекомендуемая палитра:

- Работа: спокойный серо-синий или графитовый.
- Дети: нежный голубой.
- Дни рождения: мягкий розовый.
- Дом: светлый персиковый.
- Здоровье: мятный.
- Личное: лиловый.

Основная тема интерфейса — нежная лиловая, но категории должны ясно различаться.

## 8. Приоритеты

У каждой обычной задачи есть приоритет:

- Высокий
- Обычный
- Низкий

Приоритет отображается маленьким значком или тонкой полоской слева на карточке задачи.

Рекомендуемая логика значков:

- высокий — заметный теплый акцент;
- обычный — спокойный нейтральный акцент;
- низкий — мягкий светлый акцент.

Приоритет не должен заменять цвет категории. Цвет категории остается главным способом сортировки задач.

Нельзя делать фон карточки одновременно цветом категории и цветом приоритета. Чтобы карточки не выглядели пестро, цвет категории используется для основной маркировки, а приоритет показывается только небольшим дополнительным индикатором.

## 9. Типы записей

В приложении есть два смысловых типа записей:

- задача;
- день рождения.

День рождения технически может храниться как задача категории "Дни рождения", но в интерфейсе должен отличаться отдельной иконкой, цветом и подписью "ДР".

## 10. Поля задачи

Форма задачи должна содержать:

- название;
- категория;
- дата;
- признак "Без времени";
- время начала;
- время окончания;
- приоритет;
- повторение;
- заметка.

Если заметка заполнена, она отображается в карточке задачи под названием обычным нежирным текстом. Если заметки нет, строка заметки не выводится. Для дней рождения автозаметка `ДР` не должна дублироваться под названием, потому что для нее уже есть отдельная плашка `ДР`.

Обязательные поля:

- название;
- категория;
- дата.

Если задача отмечена как "Без времени", поля времени не обязательны и не используются.

Если задача не отмечена как "Без времени", время начала и время окончания должны быть заполнены.

Дополнительных полей не нужно.

## 11. Время задач

Для задач с временем пользователь выбирает:

- время начала;
- время окончания.

Время выбирается с шагом 15 минут.

Допустимый формат времени: `HH:MM`.

Примеры значений:

- `08:00`
- `08:15`
- `08:30`
- `08:45`
- `09:00`

Время окончания должно быть позже времени начала.

Если пользователь выбрал некорректный интервал, приложение должно показать понятное предупреждение и не сохранять задачу.

## 12. Задачи без времени

Задачи без времени показываются вверху соответствующего дня.

Они не отображаются внутри почасовой сетки.

Не нужно писать "весь день", если задача без времени. Достаточно разместить ее в верхнем блоке дня.

## 13. Конфликты времени

Если пользователь создает или редактирует задачу с временем, и ее интервал пересекается с другой задачей в этот же день, приложение должно показать предупреждение.

Предупреждение не должно блокировать сохранение окончательно. Пользователь должен иметь выбор:

- сохранить задачу несмотря на конфликт;
- вернуться к редактированию.

Конфликт проверяется только для задач с временем.

Задачи без времени в проверке конфликтов не участвуют.

## 14. Повторение задач

Приложение должно поддерживать варианты повторения:

- Не повторять
- Каждый день
- Каждую неделю
- Каждый месяц
- Каждый год
- По выбранным дням недели

Дата окончания повтора не нужна. Повторяющиеся задачи считаются бессрочными.

Для повтора по дням недели пользователь может выбрать несколько дней, например понедельник и среду.

Дни рождения автоматически повторяются каждый год.

## 15. Редактирование повторяющихся задач

Если пользователь нажимает "Редактировать" у повторяющейся задачи, приложение должно уточнить, что изменить:

- только эту дату;
- всю серию.

Если пользователь выбирает "только эту дату":

- исходная повторяющаяся задача получает исключение для выбранной даты;
- создается отдельная обычная задача на выбранную дату с измененными данными.

Если пользователь выбирает "всю серию":

- изменения применяются к исходной повторяющейся задаче;
- все будущие и прошлые отображаемые повторения строятся уже по новым данным;
- ранее созданные отдельные исключения не удаляются автоматически.

## 16. Удаление задач

Удаление всегда выполняется через красивое модальное окно внутри страницы.

Обычные задачи:

- пользователь нажимает "Удалить";
- приложение показывает подтверждение;
- после подтверждения задача удаляется из `localStorage`.

Повторяющиеся задачи:

- при удалении удаляется вся серия;
- приложение должно явно написать в подтверждении: "Будет удалена вся серия повторяющейся задачи";
- после подтверждения исходная повторяющаяся задача удаляется из `localStorage`.

Отдельно удалять один экземпляр повторяющейся задачи не нужно.

Кнопка "Очистить все данные" не нужна.

## 17. Перенос задач

Перенос выполняется через отдельную кнопку "Перенести" на карточке задачи.

После нажатия открывается форма переноса, где пользователь выбирает:

- новую дату;
- новое время начала и окончания, если задача была с временем;
- возможность убрать время и сделать задачу задачей без времени;
- возможность добавить время, если задача была без времени.

Если переносится повторяющаяся задача, приложение должно уточнить:

- перенести только эту дату;
- изменить всю серию.

Для переноса только одной даты использовать ту же логику исключений, что и при редактировании одного экземпляра.

## 18. Дни рождения

День рождения создается через ту же форму задачи, но с категорией "Дни рождения".

Для дня рождения нужны:

- имя или название в поле "Название";
- дата;
- категория "Дни рождения";
- заметка по желанию.

Возраст считать не нужно.

День рождения:

- всегда повторяется каждый год;
- отображается отдельным цветом;
- имеет иконку;
- имеет подпись "ДР";
- не требует времени.

Если пользователь выбрал категорию "Дни рождения", приложение должно автоматически считать такую запись ежегодно повторяющейся.

## 19. Фильтры

В интерфейсе нужны фильтры по категориям.

Фильтры должны поддерживать выбор нескольких категорий одновременно.

Варианты фильтров:

- Работа
- Дети
- Дни рождения
- Дом
- Здоровье
- Личное

Также должна быть возможность быстро показать все категории.

Выбранные фильтры не нужно сохранять после перезагрузки страницы.

Поиск по названию задачи не нужен.

## 20. Представление "День"

Режим "День" — основной режим приложения.

Он должен содержать:

- дату дня;
- блок задач без времени вверху;
- компактное расписание только по занятым временным интервалам;
- задачи с временем отдельными плашками с диапазоном времени;
- цветовую маркировку категорий;
- значок приоритета;
- кнопки "Редактировать", "Перенести", "Удалить" на каждой карточке задачи.

Пустая почасовая сетка на 24 часа не нужна. Если на день занято время `10:00-11:00`, в расписании показывается только эта плашка, без пустых строк остальных часов.

Если в дне нет задач, календарь остается пустым. Дополнительный текст вроде "На этот день задач нет" не нужен.

## 21. Представление "Неделя"

Режим "Неделя" должен отображать 7 колонок по дням недели.

Требования:

- неделя начинается с понедельника;
- каждая колонка содержит дату и день недели;
- вверху каждой колонки отображаются задачи без времени;
- ниже отображаются задачи с временем;
- задачи сортируются по времени начала;
- категории отображаются цветом;
- дни рождения отображаются цветом, иконкой и подписью "ДР".

На ноутбуке колонки должны быть видны как недельная сетка. Если ширины не хватает, допускается горизонтальная прокрутка.

## 22. Представление "Месяц"

Режим "Месяц" должен быть классической календарной сеткой.

Требования:

- неделя начинается с понедельника;
- сетка включает дни предыдущего и следующего месяца, если это нужно для заполнения недель;
- дни не текущего месяца визуально приглушены;
- в ячейках дней отображаются краткие карточки или метки задач;
- дни рождения отображаются отдельным цветом, иконкой и подписью "ДР";
- если задач много, ячейка должна оставаться аккуратной и не ломать сетку;
- клик по ячейке дня открывает режим "День" для выбранной даты.

## 23. Представление "Год"

Режим "Год" должен показывать обзор месяцев без тяжелой сетки из 365 дневных ячеек.

Требования:

- отображаются все 12 месяцев выбранного года;
- каждый месяц представлен компактным блоком;
- для каждого месяца показывается общее количество задач и дней рождения;
- внутри блока месяца показываются 2-3 маленькие цветные отметки категорий, чтобы быстро понять насыщенность и типы событий;
- дни рождения должны быть заметны среди отметок;
- задача годового вида — быстро понять, какие месяцы насыщены событиями;
- полноценные мини-календари на каждый месяц в годовом виде не нужны;
- клик по карточке месяца открывает режим "Месяц" для выбранного месяца.

## 24. Форма создания, редактирования и переноса

Постоянная правая панель не используется.

На основной панели календаря есть кнопка `+ Добавить новую задачу`.

Создание задачи:

- пользователь нажимает `+ Добавить новую задачу`;
- форма раскрывается на основной панели под заголовком календаря;
- форму можно закрыть кнопкой `Отмена` или крестиком `×` в правом верхнем углу формы.

Редактирование и перенос:

- пользователь нажимает иконку редактирования или переноса на карточке задачи;
- форма открывается модальным окном поверх календаря с затемнением фона;
- форма сразу заполняется данными выбранной задачи;
- форму можно закрыть кнопкой `Отмена` или крестиком `×` в правом верхнем углу формы.

Карточка задачи также поддерживает двойной щелчок: двойной щелчок по обычной задаче открывает модальное редактирование, а двойной щелчок по повторяющейся задаче сначала открывает уточнение "Только эту дату" или "Всю серию".

На экранах шириной меньше `1024px` и на телефоне страница не должна ломаться: календарные сетки могут прокручиваться внутри своих контейнеров, а модальные окна должны помещаться по ширине экрана и прокручиваться по высоте при необходимости.

## 25. Сценарии использования

### 25.1. Пользователь открывает приложение

1. Пользователь открывает `index.html` в браузере.
2. Приложение показывает название "План на день".
3. Приложение открывает режим "Неделя".
4. Приложение показывает сегодняшнюю дату.
5. Приложение загружает данные из `localStorage`.
6. При первом открытии приложение добавляет тестовые задачи.

### 25.2. Пользователь переключает режим календаря

1. Пользователь нажимает "День", "Неделя", "Месяц" или "Год".
2. Приложение меняет вид календаря.
3. Активная дата сохраняется.
4. Задачи отображаются согласно выбранному режиму.

### 25.3. Пользователь переходит по датам

1. Пользователь нажимает назад или вперед.
2. Приложение меняет дату, неделю, месяц или год в зависимости от текущего режима.
3. Календарь перерисовывается.

### 25.4. Пользователь возвращается к сегодняшнему дню

1. Пользователь нажимает "Сегодня".
2. Приложение ставит активную дату на сегодняшнюю.
3. Календарь перерисовывается.

### 25.5. Пользователь создает задачу без времени

1. Пользователь заполняет название, категорию и дату.
2. Пользователь включает признак "Без времени".
3. Пользователь выбирает приоритет и повторение при необходимости.
4. Пользователь нажимает "Сохранить".
5. Приложение проверяет обязательные поля.
6. Приложение сохраняет задачу в `localStorage`.
7. Задача появляется вверху выбранного дня.

### 25.6. Пользователь создает задачу с временем

1. Пользователь заполняет название, категорию и дату.
2. Пользователь выключает признак "Без времени".
3. Пользователь выбирает время начала и окончания с шагом 15 минут.
4. Пользователь выбирает приоритет и повторение при необходимости.
5. Пользователь нажимает "Сохранить".
6. Приложение проверяет обязательные поля и корректность времени.
7. Приложение проверяет пересечение с другими задачами.
8. При конфликте показывает предупреждение.
9. Если пользователь подтверждает сохранение, задача сохраняется.
10. Задача появляется в компактном расписании занятых интервалов.

### 25.7. Пользователь создает день рождения

1. Пользователь вводит имя или название.
2. Пользователь выбирает категорию "Дни рождения".
3. Пользователь выбирает дату.
4. Пользователь нажимает "Сохранить".
5. Приложение сохраняет запись как ежегодно повторяющуюся.
6. Запись отображается в календаре отдельным цветом, иконкой и подписью "ДР".

### 25.8. Пользователь редактирует обычную задачу

1. Пользователь нажимает иконку "Редактировать" на карточке задачи или делает двойной щелчок по карточке.
2. Данные задачи открываются в модальном окне поверх календаря.
3. Пользователь меняет поля.
4. Пользователь нажимает "Сохранить".
5. Приложение проверяет данные.
6. Приложение обновляет запись в `localStorage`.
7. Календарь перерисовывается.

Если пользователь открыл редактирование по ошибке, он может закрыть окно кнопкой `Отмена` или крестиком `×` без сохранения изменений.

### 25.9. Пользователь редактирует повторяющуюся задачу

1. Пользователь нажимает иконку "Редактировать" на карточке повторяющейся задачи или делает двойной щелчок по карточке.
2. Приложение показывает модальное уточнение: "Изменить только эту дату или всю серию?"
3. Пользователь выбирает вариант.
4. Приложение открывает данные в модальном окне поверх календаря.
5. После сохранения применяет выбранную логику: исключение для одной даты или изменение всей серии.

### 25.10. Пользователь переносит задачу

1. Пользователь нажимает "Перенести".
2. Приложение открывает форму переноса в модальном окне поверх календаря.
3. Пользователь выбирает новую дату.
4. Если нужно, пользователь меняет время.
5. Пользователь сохраняет перенос.
6. Приложение проверяет время и конфликты.
7. Задача появляется на новой дате.

### 25.11. Пользователь удаляет задачу

1. Пользователь нажимает "Удалить".
2. Приложение показывает модальное подтверждение.
3. Пользователь подтверждает удаление.
4. Приложение удаляет задачу из `localStorage`.
5. Календарь перерисовывается.

### 25.12. Пользователь удаляет повторяющуюся задачу

1. Пользователь нажимает "Удалить" у повторяющейся задачи.
2. Приложение показывает предупреждение, что будет удалена вся серия.
3. Пользователь подтверждает удаление.
4. Приложение удаляет исходную повторяющуюся задачу из `localStorage`.
5. Календарь перерисовывается.

### 25.13. Пользователь фильтрует календарь

1. Пользователь выбирает одну или несколько категорий.
2. Приложение показывает только задачи выбранных категорий.
3. Пользователь может вернуть отображение всех категорий.
4. После перезагрузки страницы фильтры сбрасываются.

### 25.14. Пользователь проваливается из общего вида в подробный

1. В режиме "Год" пользователь нажимает на карточку месяца.
2. Приложение открывает режим "Месяц" для выбранного месяца.
3. В режиме "Месяц" пользователь нажимает на ячейку дня.
4. Приложение открывает режим "День" для выбранной даты.
5. В режиме "Неделя" пользователь нажимает на колонку дня вне карточки задачи.
6. Приложение открывает режим "День" для выбранной даты.

## 26. Хранение данных

Использовать ключ `dayPlanAppData` в `localStorage`.

Рекомендуемая структура:

```json
{
  "version": 1,
  "demoSeeded": true,
  "tasks": []
}
```

Рекомендуемая структура задачи:

```json
{
  "id": "task_1720000000000",
  "title": "Занятие ребенка",
  "category": "children",
  "date": "2026-08-18",
  "isAllDay": false,
  "startTime": "15:00",
  "endTime": "16:00",
  "priority": "normal",
  "repeat": {
    "type": "weekly",
    "weekdays": []
  },
  "note": "",
  "excludedDates": [],
  "sourceRecurringId": null,
  "createdAt": "2026-08-18T09:00:00.000Z",
  "updatedAt": "2026-08-18T09:00:00.000Z"
}
```

Значения `category`:

- `work`
- `children`
- `birthday`
- `home`
- `health`
- `personal`

Значения `priority`:

- `high`
- `normal`
- `low`

Значения `repeat.type`:

- `none`
- `daily`
- `weekly`
- `monthly`
- `yearly`
- `weekdays`

Для задачи без повторения:

```json
"repeat": {
  "type": "none",
  "weekdays": []
}
```

Для повтора по дням недели:

```json
"repeat": {
  "type": "weekdays",
  "weekdays": [1, 3]
}
```

Где `1` — понедельник, `7` — воскресенье.

## 27. Логика повторений

Повторяющиеся задачи не нужно физически создавать на каждую дату.

При построении календаря приложение должно вычислять, какие повторяющиеся задачи попадают в отображаемый период.

Правила:

- `daily` — каждый день начиная с даты задачи;
- `weekly` — каждую неделю в тот же день недели, начиная с даты задачи;
- `monthly` — каждый месяц в тот же день месяца, начиная с даты задачи;
- `yearly` — каждый год в тот же день и месяц, начиная с даты задачи;
- `weekdays` — каждую неделю в выбранные дни недели, начиная с даты задачи.

Если дата есть в `excludedDates`, экземпляр на эту дату не отображается.

Для дней рождения использовать `repeat.type = "yearly"` автоматически.

## 28. Тестовые данные

При первом открытии нужно добавить несколько демонстрационных записей:

- рабочая задача с временем;
- детское занятие с временем;
- домашняя задача без времени;
- задача по здоровью;
- личная задача;
- день рождения.

Тестовые данные добавляются только один раз. Для этого использовать флаг `demoSeeded: true`.

Даты тестовых задач должны генерироваться динамически относительно текущей даты пользователя, а не быть захардкоженными.

Примеры:

- рабочая задача на сегодня;
- детское занятие на завтра;
- домашняя задача без времени на сегодня;
- задача по здоровью через несколько дней;
- личная задача на текущей неделе;
- день рождения примерно через месяц.

## 29. Валидация

При сохранении задачи проверять:

- название заполнено;
- категория выбрана;
- дата выбрана;
- если задача с временем, время начала заполнено;
- если задача с временем, время окончания заполнено;
- время окончания позже времени начала;
- для повтора по дням недели выбран хотя бы один день.

Ошибки показывать рядом с формой или в понятном блоке внутри модального окна/раскрывающейся формы.

## 30. Визуальный стиль

Стиль: уютный личный планировщик с мягкими карточками.

Требования:

- нежная лиловая основная тема;
- светлый фон;
- аккуратные карточки задач;
- понятные цветные категории;
- без перегруженности;
- хорошая читаемость на ноутбуке;
- плавные, но ненавязчивые состояния наведения;
- кнопки и формы должны выглядеть современно и спокойно.
- модальные окна должны быть аккуратными, с затемнением фона и понятной кнопкой закрытия `×` в форме задачи.

Интерфейс должен быть удобен на ноутбуке. На телефоне страница должна не ломаться: элементы могут перестраиваться в одну колонку, календарные сетки могут прокручиваться.

## 31. Что не нужно делать

В первой версии не нужно:

- поиск по задачам;
- пользовательские категории;
- изменение цветов категорий;
- отметка выполнения задачи;
- напоминания;
- расчет возраста для дней рождения;
- экспорт данных;
- импорт данных;
- очистка всех данных одной кнопкой;
- серверная часть;
- база данных;
- авторизация;
- drag-and-drop перенос задач;
- внешние библиотеки.

Перенос задач в первой версии осуществляется строго через кнопку "Перенести" и форму переноса. Перетаскивание задач мышью не реализуется.

## 32. Бэклог второй версии

На вторую версию стоит вынести отметку выполнения задачи.

Возможный вариант:

- добавить чекбокс на карточку задачи;
- при отметке визуально зачеркивать задачу;
- сохранять состояние выполнения в `localStorage`;
- отдельно продумать, как выполнение работает для повторяющихся задач.

В первой версии отметка выполнения не реализуется, чтобы не усложнять логику повторяющихся задач и исключений.

## 33. Критерии готовности

Приложение считается готовым, если:

- проект состоит из `index.html`, `style.css`, `script.js`;
- интерфейс полностью на русском языке;
- при открытии показывается режим "Неделя" и сегодняшняя дата;
- данные сохраняются в `localStorage`;
- после перезагрузки страницы задачи остаются;
- можно создать задачу без времени;
- можно создать задачу с диапазоном времени;
- время выбирается с шагом 15 минут;
- при конфликте времени появляется предупреждение;
- можно создать день рождения;
- день рождения повторяется каждый год;
- можно редактировать задачу;
- при редактировании повторяющейся задачи есть уточнение про одну дату или всю серию;
- можно перенести задачу через кнопку;
- можно удалить задачу через модальное подтверждение;
- при удалении повторяющейся задачи удаляется вся серия;
- есть режимы день, неделя, месяц, год;
- в режиме день видны задачи без времени и только занятые временные интервалы;
- в режиме неделя есть 7 колонок с понедельника;
- в режиме месяц есть классическая сетка с днями соседних месяцев;
- в режиме год есть компактный обзор 12 месяцев с количеством задач и маленькими отметками категорий;
- из режима год можно открыть месяц, из месяца — день, из недели — день;
- редактирование и перенос открываются модальным окном;
- карточку задачи можно открыть на редактирование двойным щелчком;
- заметка отображается под названием задачи только если она заполнена;
- фильтры позволяют выбрать несколько категорий;
- поиск отсутствует;
- тестовые данные создаются динамически относительно текущей даты;
- на экранах меньше `1024px` интерфейс перестраивается, календарные сетки остаются доступными, а модальные окна помещаются на экране;
- перенос задач выполняется через кнопку "Перенести" и форму переноса;
- интерфейс удобен на ноутбуке;
- на телефоне страница не ломается.
